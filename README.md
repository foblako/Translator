# Транслятор DialogueScript на базе ANTLR4

Этот проект представляет собой реализацию компилятора-интерпретатора для предметно-ориентированного языка **DialogueScript (DS)**, предназначенного для написания нелинейных диалогов в компьютерных играх. Транслятор разработан на языке C++17 с использованием генератора лексеров и парсеров ANTLR4.

В проекте используются:
*   **Грамматика (`grammar/DialogueScript.g4`)** — описание синтаксиса и токенов языка.
*   **Парсер и лексер** — код, автоматически генерируемый ANTLR4 из файла грамматики.
*   **Интерпретатор (`src/DialogueInterpreter.h/.cpp`)** — класс, обходящий дерево разбора (Visitor) и выполняющий команды.

## Архитектура проекта

Проект разделен на следующие основные компоненты:

*   **`CMakeLists.txt`**: Скрипт сборки проекта. Использует модуль `FetchContent` для автоматической загрузки C++ Runtime библиотеки ANTLR4 и скачивания JAR-файла инструмента ANTLR Tool. Это избавляет пользователя от необходимости вручную устанавливать C++ библиотеки ANTLR4. Автоматически генерирует лексер, парсер и базовый класс Visitor.
*   **`grammar/DialogueScript.g4`**: Файл грамматики в формате ANTLR4. Описывает как лексические правила (токены, строки, числа), так и синтаксические конструкции (блоки `start`, ветки диалогов `branchDecl`, реплики `npcStmt`, выбор `choiceStmt`, условия `ifStmt`, переходы `gotoStmt` и действия `actionStmt`).
*   **`src/WorldState.h`**: Класс, отвечающий за хранение динамического состояния мира во время выполнения диалога (инвентарь игрока и булевы флаги).
*   **`src/BranchRegistry.h`**: Реестр, хранящий ссылки (указатели на контексты узлов дерева разбора ANTLR) на все объявленные в коде ветки диалога для обеспечения быстрых переходов и валидации.
*   **`src/DialogueErrorListener.h`**: Кастомный обработчик ошибок (наследует `antlr4::BaseErrorListener`). Позволяет перехватывать синтаксические ошибки, возникающие при парсинге, выводить их в `stderr` и корректно прерывать выполнение.
*   **`src/DialogueInterpreter.h` / `src/DialogueInterpreter.cpp`**: Ядро интерпретатора. Класс наследуется от `DialogueScriptBaseVisitor`. Реализует два прохода:
    1.  *Статический проход (Static Analysis)*: Собирает все ветки диалога, проверяет наличие стартовой ветки (`start`), выявляет дубликаты веток и некорректные переходы (`goto`).
    2.  *Проход выполнения (Execution)*: Исполняет логику игры, начиная со стартовой ветки. Отслеживает условные ветвления, обрабатывает пользовательский ввод (`choice`), изменяет состояние (`take_item`, `give_item`) и выводит реплики в `stdout`.
*   **`src/main.cpp`**: Точка входа в программу. Открывает файл, указанный в аргументах командной строки, инициализирует входной поток ANTLR, лексер, парсер и запускает интерпретатор. Возвращает код 0 при успешном выполнении и 1 при ошибках (синтаксических или семантических).
*   **`examples/`**: Набор текстовых файлов с примерами программ на DialogueScript. Содержит корректные скрипты (`valid/`) и скрипты с преднамеренными ошибками (`invalid/`) для тестирования.
*   **`examples/run_tests.sh`**: Bash-скрипт для автоматического прогона всех примеров через скомпилированный транслятор и сверки ожидаемых кодов возврата.
*   **`docker/`**: Файлы для запуска и сборки транслятора в изолированном Docker-контейнере.
*   **`docs/`**: Документация, включая спецификацию языка.

## Требования к системе

Для сборки транслятора из исходных кодов вам понадобятся:

1.  Компилятор с поддержкой **C++17** (GCC 7+, Clang 5+, MSVC 2017+).
2.  **CMake** версии 3.16 или выше.
3.  **Java JRE** (версии 11 и выше). Java необходима *только* на этапе сборки для запуска инструмента ANTLR Tool (который генерирует C++ код из грамматики).

## Сборка проекта

### В среде Linux / macOS / WSL

Сборка осуществляется стандартными средствами CMake. Библиотека ANTLR C++ Runtime загружается автоматически.

```bash
# Клонируем проект и переходим в его директорию
# Создаем директорию для сборки и конфигурируем проект
cmake -B build

# Собираем проект (используйте -j для многопоточной сборки, например -j4)
cmake --build build -j$(nproc)
```

Исполняемый файл транслятора будет создан по пути `./build/main`.

### В среде Docker

Если вы не хотите устанавливать CMake и Java локально, вы можете использовать Docker:

```bash
# Сборка образа и запуск всех тестов
docker compose -f docker/docker-compose.yml build tests
docker compose -f docker/docker-compose.yml run --rm tests

# Запуск интерпретатора для конкретного файла
docker compose -f docker/docker-compose.yml run --rm translator run /workspace/examples/valid/quest_intro.txt
```

## Использование транслятора

Транслятор принимает путь к файлу с исходным кодом в качестве аргумента командной строки:

```bash
./build/main <путь_к_файлу>
```

**Примеры запуска:**

Запуск корректного диалога:
```bash
./build/main ./examples/valid/quest_intro.txt
```

При успешном выполнении программа интерактивно выводит реплики и ожидает пользовательского ввода для конструкций выбора (`choice`). По окончании диалога программа завершается с кодом `0`.

Запуск файла с синтаксической ошибкой:
```bash
./build/main ./examples/invalid/syntax_error.txt
```

Программа выведет сообщение об ошибке с указанием строки и символа в `stderr` и завершится с кодом `1`.

## Запуск автотестов

Скрипт `run_tests.sh` проверяет, что транслятор корректно обрабатывает правильные примеры (завершается без ошибок) и правильно распознает некорректные примеры (завершается с ненулевым кодом).
*Примечание: скрипт автоматически передает ввод (число 1) для прохождения интерактивных развилок.*

```bash
chmod +x ./examples/run_tests.sh
./examples/run_tests.sh ./build/main
```

Пример вывода:
```text

──────────────────────────────────────────

  PASS  valid/shop_dialogue.txt

  PASS  invalid/unknown_branch.txt
```
